# Evaluation protocol

Aggregate F1 is insufficient for a safety release. Every published result should
record the profile, exact base-model revision, tokenizer and prompt template,
runtime and precision, dataset provenance, immutable split, threshold-selection
procedure, random seed, and confusion matrix.

## Required split discipline

1. Fit axes and gates on training data.
2. Select thresholds on a separate calibration split.
3. Report primary metrics once on a locked held-out split.
4. Run external benchmarks without tuning on them.

Do not call calibration measurements held-out performance. The v0.1 Qwen metric
is intentionally labeled `calibration` because its threshold was selected on the
same energy samples.

## Required metrics

- Precision, recall, F1, accuracy, false-positive rate, and confusion matrix.
- Per-category recall and false-positive rate.
- Confidence intervals generated by bootstrap resampling.
- Boundary-route rate and end-to-end Tier 1/Tier 2 performance.
- Results on benign hard negatives, prompt injection, obfuscation, multilingual
  content, long context, and multi-turn conversations.
- Latency, throughput, memory use, and percentage overhead against an unmodified
  runtime on the same hardware.

## Release claims

Each performance statement must link to a machine-readable report. Claims should
name the profile and split, for example: “Profile X measured F1 Y on locked suite
Z.” Do not publish ranges assembled from different models or experimental runs as
if they describe one supported product.
